# 📋 Дополнительные реализации

## После проверки выполнения плана были доработаны следующие пункты:

### 1. ✅ Оптимизация Docker Compose

**Файл**: `/workspace/docker-compose.yml`

Добавлены лимиты ресурсов для всех основных сервисов:

- **app**: 0.5 CPU, 1GB RAM (резерв: 0.25 CPU, 512MB)
- **bot**: 0.3 CPU, 512MB RAM (резерв: 0.1 CPU, 256MB)  
- **sandbox**: 0.5 CPU, 512MB RAM (резерв: 0.2 CPU, 256MB)

Это обеспечивает работу в рамках ограниченных ресурсов VM (2 CPU, 4GB RAM).

### 2. ✅ Обновление marka_passport.json

**Файл**: `/workspace/marka_passport.json`

- Заменено упоминание "Weaviate" на "GraphitiMemory (Neo4j)"
- Упрощена структура типов памяти - теперь единый тип "Episodes"
- Обновлены API методы на актуальные (create_episode, search_episodes и т.д.)

### 3. ✅ Базовая поддержка Webhooks

**Файл**: `/workspace/main.py`

Добавлены новые API endpoints:

- **POST /webhooks/subscribe** - подписка на события
- **DELETE /webhooks/unsubscribe** - отписка от событий
- **GET /webhooks/list** - список активных подписок
- **send_webhook_event()** - функция для отправки событий

Это позволяет внешним системам получать уведомления о событиях в Mark.

## ⚠️ Что все еще требует внимания:

### 1. Интеграция webhooks с Event Bus
Сейчас webhooks работают отдельно. Нужно интегрировать с Event Bus, чтобы автоматически отправлять все события системы.

### 2. Персистентность планов
Планы все еще хранятся только в памяти процесса. Нужна интеграция с PostgreSQL.

### 3. Реальное выполнение планов
execute_plan() остается заглушкой. Требуется интеграция с TaskExecutor.

### 4. Лимиты для остальных сервисов
Neo4j, Redis, PostgreSQL не имеют лимитов ресурсов в docker-compose.yml.
