# **Эволюция Песочницы Марка (Sandbox Roadmap)**

> Документ для проекта «Марк»  
> Описание уровней развития песочницы, технических возможностей и задач для перехода между ними.

---

## **Sandbox v1 — MVP (текущий уровень)**

### **Что умеет**
- Выполнение одной команды через `/sandbox/exec`.
- Копирование проекта в контейнер: `/sandbox/sync`.
- Получение stdout и stderr.
- Docker-контейнер с изоляцией.
- Ручное определение, какие папки копируются.

### **Технические детали**
- Контейнер `sandbox` на базе `python:3.10-slim`.
- Volume: `dev_sandbox`.
- Команды идут через FastAPI.
- Без ограничения времени и ресурсов.

### **Задачи завершены**
- [x] Docker-сервис `sandbox` добавлен.
- [x] Команды `/sandbox/sync`, `/sandbox/exec` работают.
- [x] Стандартные папки (`core_docs`, `rag`, `utils`) копируются.

## **Sandbox v2 — Генерация и выполнение файлов**

### **Что добавляется**
- Возможность создавать файлы с кодом:  
  `/sandbox/write script.py <<< 'print("Hello")'`
- Возможность запускать свои файлы:  
  `/sandbox/run script.py`
- Ведение логов всех запусков.
- Ограничения по CPU, RAM и времени выполнения.
- Защита от зацикливания (таймаут).

### **Технические детали**
- Использовать `subprocess.run()` с `timeout=30`.
- Docker-ограничения:
  - `mem_limit: 512m`
  - `cpus: 0.5`
- Добавить `sandbox_logger.py`, который пишет:
  - имя файла, дата, результат, ошибки.
- Простой файлобмен: писать код в `dev_sandbox/`, читать оттуда.

### **Что нужно сделать**
- [ ] Добавить эндпоинт `/sandbox/write`.
- [ ] Добавить эндпоинт `/sandbox/run`.
- [ ] Добавить лог `sandbox_logs.txt` в volume.
- [ ] Добавить ограничения ресурсов в `docker-compose.yml`.
- [ ] Таймаут при запуске файлов.
- [ ] Обработка ошибок (если скрипт упал).

## **Sandbox v3 — Конструктор инструментов**

### **Что добавляется**
- Поддержка цепочек команд: скрипт 1 > скрипт 2 > скрипт 3.
- Создание и исполнение простых «мини-инструментов».
- Возможность временной установки зависимостей (pip install).
- Планирование задач на выполнение (очередь).

### **Технические детали**
- Планировщик `APScheduler` внутри `app`, запускает скрипты по расписанию.
- Поддержка venv внутри sandbox-контейнера:
  ```bash
  python -m venv venv && source venv/bin/activate && pip install ...
  ```
- Реестр инструментов (`tools.json`) — список известных утилит.
- Новый эндпоинт: `/sandbox/plan_tool`, принимает JSON-структуру плана.
- Возможность создавать chain-файлы: `run_chain.sh`.

## **Sandbox v4 — Творческая лаборатория**

### **Что добавляется**
- Хранение разных версий скриптов: `v1`, `v2`, `v3`.
- Возможность сравнивать выходы разных версий.
- Автоматическое создание Markdown-отчётов:
  - код,
  - результат,
  - выводы.
- Система фиксации гипотез и их проверок.

### **Технические детали**
- Структура файлов:
  ```
  sandbox/
  L-- experiments/
      L-- idea_xyz/
          +-- v1/
          +-- v2/
          L-- report.md
  ```
- Автоматическая генерация `report.md` после запуска `vN`.
- Добавить команду `/sandbox/compare idea_xyz`.

## **Sandbox ? — Пространство разума**

### **Что добавляется**
- Внутренний дневник: "Что я изучал сегодня", "Какие выводы сделал".
- Цикл саморазвития:  
  > Вопрос > Идея > Скрипт > Тест > Вывод > Новое знание.
- Хранение гипотез, экспериментов, опыта.
- Возможность вызывать `reflect()` и получать анализ за день/неделю.
- Создание новых цепочек без участия пользователя.

### **Технические детали**
- Класс `ExperimentLog` в Weaviate.
- Скрипт `daily_reflection.py` — парсит sandbox_logs, строит отчёт.
- Рефлексивный интерфейс через Telegram:  
  `/sandbox/reflect today`  
  `/sandbox/idea "Как проверить X?"`
