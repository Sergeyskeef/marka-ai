# Марк

Личный ИИ-партнёр в Telegram: разговор, память, исследование, рабочие файлы, выполнение кода и отложенные поручения. Использует **твой вход в Codex через ChatGPT**; отдельный платный API-ключ не нужен. Расходуется общая квота подписки.

Марк сохраняет разговоры и результаты действий, ищет прошлый опыт по словам и смыслу, продолжает длинные задачи из сохранённого состояния. Уроки связываются с реальными запусками и твоей оценкой. Удачный скрипт можно сохранить как повторно используемый навык. Это обучение через память, процедуры и проверяемые изменения кода; веса основной модели не меняются.

## Запуск на Linux-сервере

Нужны Docker Engine с Compose, доступ к Telegram/OpenAI и подходящая подписка ChatGPT/Codex. Рекомендуемый запас: 2 GB RAM и 3 GB свободного места. Можно запускать рядом с Hermes: у Марка свои контейнеры, тома и авторизация; открытых портов нет. Локальная многоязычная модель поиска устанавливается при запуске; ей не нужен отдельный API-ключ. `MARKA_SKIP_SEMANTIC=1 ./scripts/start.sh` оставляет поиск по словам.

```bash
git clone https://github.com/Sergeyskeef/marka-ai.git
cd marka-ai
./scripts/start.sh
```

`setup` скрыто запросит токен **нового** бота из BotFather и выдаст `/start <одноразовый код>`. `login` предложит открыть официальный адрес и войти в твой ChatGPT. После запуска отправь код своему боту в личный чат — он привяжется только к тебе. Если код потерян или прошло 24 часа: `docker compose run --rm --no-deps mark pair`.

На новой ВМ вход в Codex необходим один раз. Не копируй OAuth-файл Hermes: у него отдельная цепочка обновления токенов. Официальная схема: [Codex authentication](https://learn.chatgpt.com/docs/auth), [non-interactive execution](https://learn.chatgpt.com/docs/non-interactive-mode). Если device login выключен, включи его в настройках безопасности аккаунта; альтернативы приведены в документации.

## Что можно поручить

Обычным текстом: «Помоги разобраться в идее», «Исследуй эти источники и сделай отчёт», «Создай скрипт, проверь его и пришли файл», «Через час напомни проверить результат». «Запомни: я предпочитаю короткие ответы» сохраняет твою формулировку без обращения к модели. Можно приложить текст, CSV, Markdown, JSON или исходный код в UTF-8 до 512 KiB и написать поручение в подписи.

| Команда | Результат |
| --- | --- |
| `/remember Я предпочитаю...` | Сохранить твоё утверждение с источником |
| `/learn При такой ошибке сначала...` | Сохранить твою поправку как урок |
| `/memory слова`, `/candidates` | Посмотреть принятые знания / гипотезы |
| `/memoryid номер`, `/source номер [смещение]` | Раскрыть запись и исходное свидетельство по страницам |
| `/review`, `/why номер` | Проверить кандидатов и основания урока |
| `/good [задача] [отзыв]`, `/bad [задача] [отзыв]` | Связать оценку с конкретным результатом |
| `/learning off`, `/learning tentative`, `/learning auto` | Выбрать применение процедурного опыта |
| `/accept номер`, `/forget номер` | Принять или исключить запись из поиска |
| `/task поручение`, `/tasks` | Поставить задачу / проверить очередь |
| `/evolve что улучшить` | Изучить собственный код, проверить изменение на копии, сохранить отчёт и патч |
| `/status`, `/stop`, `/cancel номер` | Посмотреть работу / остановить всё / отменить задачу |
| `/resume номер`, `/result номер` | Продолжить задачу / получить сохранённый итог |
| `/progress [номер]`, `/extend номер` | План, проверки, бюджет / добавить бюджет и продолжить |
| `/file путь` | Получить рабочий файл |

По умолчанию: 12 шагов на один проход; следующие проходы продолжаются автоматически в общем бюджете 48 решений, 64 вызовов и 15 минут на задачу. До двух отдельных консультаций модели на задачу. Перезапуск или `/resume` не обнуляет расход; `/extend` явно добавляет бюджет. Общий предел — 200 вызовов Codex за сутки UTC, включая обобщения опыта. Ожидание не вызывает модель. Настройки находятся в `/state/settings.json`; `setup --model ИМЯ` выбирает модель, по умолчанию используется модель Codex CLI.

Для календарных напоминаний настрой часовой пояс:
`docker compose run --rm --no-deps mark setup --timezone UTC+03:00`.
Затем перезапусти работающий gateway: `docker compose restart mark`.
По умолчанию используется UTC; IANA-зоны вроде `Europe/Moscow` доступны при наличии
системной базы часовых поясов. Марк видит текущую дату и время каждого решения,
а квитанция напоминания и `/tasks` показывают точную дату со смещением.
Повторы задаются конечным числом запусков с интервалом после завершения предыдущего;
это не календарное правило с автоматической поправкой на летнее время.

## Память и самостоятельность

- **L0:** разговоры, исторические источники, ошибки и результаты инструментов с датой, автором и происхождением.
- **L1:** факты, предпочтения и предложения модели с источниками, статусом и историей замены; предложения применяются после подтверждения.
- **L2:** поправки владельца и процедурные уроки из результатов работы. Видны источники, независимые задачи, оценки и история использования.
- **L3:** [характер и принципы Марка](src/marka/identity.md), версионируемые вместе с кодом.

Каноническое хранилище — SQLite WAL. Поиск объединяет полнотекстовый индекс с русской нормализацией и локальные многоязычные embeddings; при отсутствии модели остаётся поиск по словам. Производные индексы можно пересоздать, а найденные отрывки раскрыть до исходного текста. Связи показывают совместные упоминания и общие задачи, не выдают их за доказанные отношения. Graphiti/Neo4j не требуются. По умолчанию сырой архив автоматически не удаляется (`retention_days=0`); положительный срок хранения задаётся явно. `/forget` исключает знание и связанные свидетельства из рабочего поиска, сохраняя аудит.

В режиме `tentative` Марк использует ограниченные процедурные подсказки с пометкой неопределённости. В `auto` заранее заданные шаблоны уроков становятся применимыми после двух независимых подтверждающих задач без отрицательного отзыва. Произвольное обобщение модели остаётся кандидатом для `/accept`. Отрицательная оценка исключает связанный урок и навык из дальнейшего применения. Обобщение запускается только по накопленному опыту, максимум восемь раз в сутки, и уступает новому поручению. Подробнее: [память](docs/MEMORY.md), [обучение](docs/LEARNING.md), [навыки](docs/SKILLS.md).

Марк работает с публичным вебом и своим каталогом, создаёт и проверяет код. При объявлении результата runtime перепроверяет коды возврата, оставшиеся ошибки и хеши файлов; противоречие возвращает агента к исправлению. Это проверка наблюдаемых действий, а не независимое доказательство качества любого ответа. Код и сохранённые навыки исполняются в отдельном контейнере без сети и секретов, во временной копии файлов. Доступа к shell основного сервера, Docker socket, публикациям и чужим чатам у модели нет. Расписания создаются по поручению владельца, с конечным числом повторов.

Из [SICA](docs/SICA.md) перенесён принцип проверяемого самоизменения: Марк читает установленный исходный код, предлагает кандидат, прогоняет исходную и изменённую версии на одинаковом наборе тестов и архивирует результат. Патч и отчёт доступны как рабочие файлы. Прохождение тестов даёт ограниченное свидетельство о конкретной правке; установка новой версии выполняется отдельно после проверки.

## Состояние реализации

Новая версия заменяет старый экспериментальный стек. Предыдущие 543 файла доступны в истории на commit [`2303443`](https://github.com/Sergeyskeef/marka-ai/tree/23034437807c5ffc5c1492b34fe979bc53b04c6a) и в ветке `archive/legacy-2026-09-18`. Противоречивые старые отчёты о готовности не являются проверками новой версии.

Проверки и фактические ограничения фиксируются в [VALIDATION.md](docs/VALIDATION.md). До добавления твоего Telegram-токена реальный диалог с новым ботом не может считаться проверенным.

Марк принимает фото и файлы PNG/JPEG в личном чате владельца: до 2 MiB, 4096 пикселей по стороне и 8 млн пикселей всего. Подпись задаёт поручение; изображение передаётся Codex только в рамках этой задачи, в том числе после перезапуска. Альбом пока обрабатывается как отдельные задачи. Подробнее: [изображения и ограничения](docs/IMAGES.md).

Голос, PDF/офисные документы, внешние изменяющие интеграции и самостоятельное внедрение изменений своего runtime пока не реализованы. Поддерживаются текстовые вложения. Публичный поиск через Bing RSS зависит от доступности сервиса; прямое чтение HTTPS-источников работает отдельно. Прохождение одного теста или успешный запуск навыка не означает, что Марк надёжно решит любой похожий случай.

## Обслуживание и разработка

```bash
docker compose logs --tail 100 mark
docker compose run --rm --no-deps mark doctor
docker compose run --rm --no-deps mark backup /state/backups/marka.sqlite3
docker compose restart mark
# Обычная остановка сохраняет тома:
docker compose down
```

Не используй `down -v`: это удалит память и авторизацию. Backup-команда копирует базу с согласованным snapshot; токен и авторизация в неё не входят. Перед переездом останови сервис и сохрани весь приватный state-том в защищённое место. На другой ВМ предпочтителен новый вход в аккаунт.

Марк также делает ежедневные локальные копии базы во время простоя и хранит семь последних снимков. Состояние видно в `/status`; при нехватке места копирование откладывается. Эти снимки не содержат фотографии, рабочие файлы и авторизацию и не заменяют полный backup state-тома.

Локальные проверки без Telegram и модели:

```bash
python -m venv .venv
# Linux: source .venv/bin/activate
# Windows: .venv\Scripts\Activate.ps1
python -m pip install -e .
python -m unittest discover -s tests -v
```

Нативная установка: [DEPLOYMENT.md](docs/DEPLOYMENT.md). Личный контекст импортируется из приватного JSON через `marka import-memory path.json`; `--accept` означает твоё явное подтверждение источников. История — `marka import-archive history.jsonl --source стабильное-имя`: сохраняются авторы, даты и исходные ID, повторный импорт не дублирует записи, прежние ответы ассистента не становятся фактами. Локальный поиск: `marka models install`, `marka models status`, `marka models index --limit 1000`. Импорт и state никогда не включаются в Git.
