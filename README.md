## 📖 О проекте

**Mark AI** - это современный самообучающийся ассистент с продвинутой системой памяти на базе графовой БД Neo4j. Проект полностью переработан с использованием OpenAI Agents SDK и реализует REAP цикл для непрерывного самообучения.

### 🎯 Ключевые особенности

- 🤖 **OpenAI Agents SDK** - нативная интеграция с GPT-5-mini
- 🧠 **Три типа памяти** - Facts, Episodes, Skills в Neo4j
- 🔄 **REAP цикл** - Reflect, Extract, Apply, Persist для самообучения
- 🔍 **Векторный поиск** - семантический поиск по памяти
- 💬 **Модульный Telegram бот** - 220 строк вместо 1500+
- 🛡️ **Rate limiting** - защита от перегрузки
- 📊 **25+ инструментов** - полный набор возможностей
- 🔧 **Чистая архитектура** - 0 TODO, -60% кода
- 🎨 **Динамические промпты** - эволюция и A/B тестирование
- 📈 **Prometheus метрики** - полный мониторинг системы
- 🔐 **Security-first** - встроенные проверки безопасности
- 🚀 **Production-ready** - автоматизированный деплой
- 🤖 **Автономная разработка** - способность самостоятельно писать код, тесты и документацию
- 📋 **Планирование проектов** - декомпозиция задач с оценкой времени
- 🧪 **Автоматическое тестирование** - запуск и анализ тестов в песочнице

### 📝 Динамическая система промптов

Революционная система управления промптами с автоматической эволюцией:

- **11-слойная архитектура контекста** (Context Window Architecture)
- **Agent Lineage Evolution (ALE)** - промпты эволюционируют на основе производительности
- **LinUCB алгоритм** для динамического выбора промптов
- **A/B тестирование** промптов в реальном времени
- **Автоматическая оптимизация** контекста для разных моделей

### 🔧 Режим разработки (Dev Mode)

Для удобства разработки и тестирования предусмотрен специальный режим, который временно отключает все ограничения.

#### Активация
```bash
# В .env файле или переменных окружения
BOT_DEV_MODE=true  # для разработки (по умолчанию)
BOT_DEV_MODE=false # для production
```

#### Что меняется в Dev Mode:
- ✅ **Все пользователи - админы** - доступны все команды без ограничений
- ✅ **Увеличенный rate limit** - 90 запросов/минуту вместо 30
- ✅ **Отладочные логи** - дополнительная информация в логах
- ✅ **Упрощенная авторизация** - не нужно добавлять свой ID в админы

#### Настройка для production:
```bash
# .env для production
BOT_DEV_MODE=false
ADMIN_USERS=123456789,987654321  # Telegram ID админов
LOG_USER_MESSAGES=true            # Логировать все сообщения
```

> ⚠️ **Важно**: Никогда не используйте `DEV_MODE=true` в production! 

Подробнее о режиме разработки: [DEV_MODE_GUIDE.md](telegram_bot/DEV_MODE_GUIDE.md)

## 📊 Event Bus и мониторинг

### Event Bus
Централизованная шина событий для связи компонентов:
- **Асинхронная публикация** событий
- **Приоритеты обработки** (CRITICAL, HIGH, NORMAL, LOW)
- **История событий** с поиском и фильтрацией
- **Статистика** по типам и источникам событий

### Типы событий
- `PLAN_CREATED`, `PLAN_EXECUTED` - события планирования
- `SANDBOX_EXECUTED`, `SANDBOX_BLOCKED` - выполнение кода
- `MEMORY_STORED`, `MEMORY_RETRIEVED` - работа с памятью
- `ERROR_OCCURRED`, `ERROR_DIAGNOSED` - обработка ошибок
- `SYSTEM_STARTUP`, `SYSTEM_SHUTDOWN` - жизненный цикл

### Event Monitor
Автоматический мониторинг всех событий системы:
- Сбор метрик производительности
- Отслеживание ошибок
- Генерация отчетов
- Визуализация статистики
