# 🤖 Автономные возможности Марка

## Обзор

Марк теперь обладает полноценными возможностями автономной разработки, позволяющими ему самостоятельно:
- Планировать и декомпозировать проекты
- Писать и рефакторить код
- Создавать и запускать тесты
- Генерировать документацию
- Учиться на результатах своей работы

## Архитектура автономности

### Основные компоненты

1. **AutonomousAgent** (`app/autonomy/autonomous_agent.py`)
   - Главный координатор автономной работы
   - Управляет уровнями автономности
   - Координирует выполнение задач

2. **TaskPlanner** (`app/autonomy/task_planner.py`)
   - Декомпозиция проектов на выполнимые задачи
   - Определение зависимостей и приоритетов
   - Оценка времени выполнения

3. **CodeGenerator** (`app/autonomy/code_generator.py`)
   - Генерация кода по описанию
   - Рефакторинг существующего кода
   - Создание тестов и документации

4. **TestRunner** (`app/autonomy/test_runner.py`)
   - Запуск тестов в песочнице
   - Анализ результатов тестирования
   - Автоматическое исправление простых ошибок

## Уровни автономности

### 1. Manual (Ручной)
- Полный контроль пользователя
- Марк выполняет только явные команды
- Подходит для критически важных задач

### 2. Assisted (Ассистированный)
- Марк предлагает решения
- Требует подтверждения перед выполнением
- Идеален для обучения и проверки

### 3. Supervised (Под наблюдением)
- Марк действует самостоятельно
- Пользователь может вмешаться в любой момент
- Оптимальный баланс автономности и контроля

### 4. Autonomous (Автономный)
- Полная автономность в рамках проекта
- Самостоятельное принятие решений
- Для хорошо определенных задач

## API Endpoints

### Управление проектами

```http
POST /api/autonomy/start_project
{
  "description": "Создать REST API для управления задачами с аутентификацией",
  "autonomy_level": "supervised"
}
```

### Выполнение отдельных задач

```http
POST /api/autonomy/execute_task
{
  "task_description": "Написать функцию для валидации email",
  "task_type": "code_generation",
  "requirements": ["Использовать regex", "Поддержка Unicode"]
}
```

### Проверка статуса

```http
GET /api/autonomy/status
```

Ответ:
```json
{
  "is_active": true,
  "autonomy_level": "supervised",
  "current_project": "REST API для задач",
  "tasks_total": 12,
  "tasks_completed": 5,
  "current_task": {
    "name": "Реализация модели User",
    "type": "code_generation",
    "priority": "high"
  }
}
```

### Остановка автономного режима

```http
POST /api/autonomy/stop
```

### Изменение уровня автономности

```http
POST /api/autonomy/set_autonomy_level/assisted
```

### Получение возможностей

```http
GET /api/autonomy/capabilities
```

## Примеры использования

### Пример 1: Создание микросервиса

```python
# Запуск проекта
response = requests.post("http://localhost:8000/api/autonomy/start_project", json={
    "description": """
    Создать микросервис для обработки изображений:
    - Загрузка изображений
    - Изменение размера
    - Применение фильтров
    - API на FastAPI
    - Тесты с pytest
    """,
    "autonomy_level": "supervised"
})

# Марк автоматически:
# 1. Создаст план проекта
# 2. Реализует API endpoints
# 3. Добавит обработку изображений
# 4. Напишет тесты
# 5. Создаст документацию
```

### Пример 2: Рефакторинг кода

```python
response = requests.post("http://localhost:8000/api/autonomy/execute_task", json={
    "task_description": "Провести рефакторинг файла app/services/user_service.py",
    "task_type": "refactoring",
    "requirements": [
        "Улучшить читаемость",
        "Добавить type hints",
        "Оптимизировать производительность"
    ]
})
```

### Пример 3: Генерация тестов

```python
response = requests.post("http://localhost:8000/api/autonomy/execute_task", json={
    "task_description": "Создать unit тесты для модуля authentication",
    "task_type": "testing",
    "requirements": [
        "Покрытие > 80%",
        "Использовать pytest",
        "Добавить тесты на edge cases"
    ]
})
```

## Интеграция с памятью Graphiti

Марк использует Graphiti для:

1. **Сохранения опыта разработки**
   - Успешные паттерны кода
   - Решения типовых проблем
   - Оптимальные подходы

2. **Обучения на ошибках**
   - Анализ неудачных попыток
   - Корректировка подходов
   - Избегание повторения ошибок

3. **Переиспользования знаний**
   - Поиск похожих проектов
   - Адаптация существующих решений
   - Ускорение разработки

## Безопасность

### Песочница для выполнения кода
- Изолированный Docker контейнер
- Ограничения ресурсов (CPU, память)
- Whitelist разрешенных команд
- AST анализ Python кода

### Контроль операций
- Все действия логируются
- Возможность отката изменений
- Ограничения на файловые операции
- Защита от вредоносного кода

## Мониторинг и метрики

Марк отслеживает:
- Время выполнения задач
- Процент успешных тестов
- Качество сгенерированного кода
- Эффективность различных подходов

Метрики доступны через Prometheus endpoint: `/metrics`

## Telegram интеграция

В Telegram боте доступны команды:
- `/autonomous` - Управление автономным режимом
- `/project` - Запуск нового проекта
- `/status` - Текущий статус работы
- `/stop` - Остановка автономного режима

## Лучшие практики

1. **Начинайте с уровня Supervised**
   - Позволяет контролировать процесс
   - Помогает понять возможности системы

2. **Четко формулируйте требования**
   - Детальное описание проекта
   - Конкретные технические требования
   - Примеры желаемого результата

3. **Используйте инкрементальный подход**
   - Разбивайте большие проекты на этапы
   - Проверяйте промежуточные результаты
   - Корректируйте направление при необходимости

4. **Мониторьте выполнение**
   - Следите за логами
   - Проверяйте качество кода
   - Анализируйте результаты тестов
