# Развёртывание 2.1

## Рядом с Hermes

Используйте отдельный каталог `/opt/marka-ai` и Compose project `marka`.
Контейнеры не публикуют порты и не подключаются к томам, auth-файлам или Docker
socket Hermes. Тома называются `marka_state` и `marka_runner`; не используйте
имена уже работающих приложений.

```bash
cd /opt/marka-ai
docker compose build
docker compose run --rm --no-deps mark setup
docker compose run --rm --no-deps mark login
docker compose run --rm --no-deps mark doctor --live
# Необязательно: локальный поиск по смыслу, без embedding API.
docker compose run --rm --no-deps mark models install
docker compose up -d
docker compose ps
```

Ввод токена скрыт. Не передавайте его через аргумент командной строки, issue,
чат или Git. `setup` записывает секрет в приватный том с режимом `0600`.
Новый login относится к той же подписке, но имеет собственное хранилище;
повторный вход существующего Hermes не выполняется.
На новой ВМ планируйте отдельный вход в Codex; наличие подписки не создаёт
авторизацию автоматически. Штатный `scripts/start.sh` проверяет существующий
вход, устанавливает модель поиска и запускает сервисы. Чтобы пропустить установку
модели: `MARKA_SKIP_SEMANTIC=1 ./scripts/start.sh`.

После `/start <код>` в личном чате проверьте: обычный ответ; `/remember` и поиск;
создание/получение файла; выполнение короткого Python-скрипта; `/stop` во время
длинной задачи; сохранение памяти после `docker compose restart mark`.
Политика обучения проверяется командой `/learning` и выбирается через
`/learning off|tentative|auto`. Источник истины — SQLite `learning_policy`,
а не поле `learning_mode` в `settings.json`.

## Ресурсы и файлы

Bot container: до 1 GB RAM, 1 CPU, 128 процессов. Runner: 512 MB RAM,
1 CPU, 64 процесса, сеть выключена. Рабочая копия runner находится на tmpfs
до 128 MiB. В неё передаются до 200 файлов / 1 MiB, возвращается до 2 MiB
артефактов, каждый до 512 KiB. Команда работает до 60 секунд.

По умолчанию новая задача получает 48 решений, 64 вызова модели, 900 секунд всего;
12 решений на один автоматически продолжаемый проход. Общий бюджет агента —
200 вызовов за сутки UTC, включая консультации и обобщения опыта. `/resume`
сохраняет расход, `/extend` явно добавляет бюджет. Вариант сохранённого навыка
с новыми аргументами или данными требует проверки нового результата.

Постоянная память, рабочие файлы, архивы навыков/экспериментов, локальная модель
поиска и Codex credentials находятся в state-томе.
Логи ротируются. Вызовы модели ограничены бюджетом, но место постоянной памяти
следует контролировать обычным мониторингом сервера. Это контейнерная изоляция
ядра Linux, не отдельная виртуальная машина.

Проверка runner без Telegram и модели:

```bash
docker compose up -d sandbox
docker compose run --rm --no-deps --entrypoint python mark scripts/container_smoke.py
```

## Обновление и откат

Во время простоя gateway автоматически создаёт согласованный снимок канонической
SQLite-базы в `/state/backups/automatic/YYYY-MM-DD.sqlite3`, не чаще одного раза
за сутки UTC. Хранятся семь последних автоматических снимков; ручные копии
в других каталогах и под другими именами не удаляются. `/status` показывает
последнее успешное копирование и неудачную попытку. После сбоя копирование
повторяется не раньше чем через час; незавершённая копия не заменяет готовую.

Перед записью учитываются страницы базы, включая ещё не перенесённые из WAL,
размер будущего снимка и запас свободного места не менее 512 MiB плюс допуск
на рост базы. При нехватке места сохраняются прежние копии. Создание и проверка
SQLite выполняются с ограничением времени, отдельно от event loop и без модели.

Это локальные копии базы на том же диске: они содержат личную память, очередь
и журнал, но не Codex auth, Telegram settings, рабочие файлы, media, исходники
навыков или производные индексы. Они помогают восстановить базу после ошибки;
для переноса или восстановления после потери сервера нужен отдельно сохранённый
полный приватный state-том, как описано ниже.

Перед обновлением зафиксируйте текущий commit и сделайте резервную копию:

```bash
docker compose stop mark
docker compose run --rm --no-deps mark backup /state/backups/before-update.sqlite3
git rev-parse HEAD
git pull --ff-only
docker compose build
docker compose run --rm --no-deps mark doctor
```

При переходе с 2.0 проверьте сохранённый срок хранения. Новый default `0` не
заменяет прежнее значение `90` в `settings.json`. Для явного перехода к хранению
сырого архива без автоматического удаления выполните **до запуска bot**:

```bash
docker compose run --rm --no-deps --entrypoint python mark -c 'from marka.config import Settings; s=Settings.load("/state"); s.retention_days=0; s.save(); print("retention_days:", s.retention_days)'
docker compose up -d
docker compose ps
```

Это меняет политику будущей очистки и не восстанавливает ранее удалённые эпизоды.
Если выбран другой срок, сохраните его явно и запустите сервис обычным
`docker compose up -d`. При открытии базы приложение добавляет необходимые таблицы
и проекции; производные индексы можно построить заново из сохранившихся источников.

Для отката кода выберите предыдущий **commit новой версии 2.x**, пересоберите
и проверьте совместимость его схемы с резервной копией. При несовместимости
восстановите согласованный снимок до обновления и соответствующий ему код.
Старый стек до `2303443` использует другую архитектуру
и не является совместимым runtime для state v2. Перед восстановлением базы
остановите bot; не подменяйте открытую SQLite-базу и её WAL отдельными файлами.
Резервные копии содержат личные данные. Не публикуйте их.

`backup` сохраняет только базу: рабочие файлы, снимки навыков, архивы экспериментов,
настройки, модели и авторизация в неё не входят. Для полного переноса остановите
bot и сохраните весь приватный state-том в защищённое место, сохраняя права файлов.
Не запускайте одновременно две копии с одним Telegram-токеном. Не используйте
`docker compose down -v`: он удалит тома. До восстановления базы остановите bot;
открытую SQLite-базу и её WAL нельзя заменять по отдельности.

## Нативный процесс без исполнения кода

Python 3.11+ и Node.js 22+, официальный `@openai/codex@0.144.1`.
Создайте отдельного непривилегированного пользователя `marka`, разместите код
в `/opt/marka-ai`, а state в `/var/lib/marka`. Пример unit-файла:
[`deploy/marka.service`](../deploy/marka.service).

```bash
cd /opt/marka-ai
python3 -m venv .venv
.venv/bin/pip install .
sudo -u marka env MARKA_DATA=/var/lib/marka .venv/bin/marka setup
sudo -u marka env MARKA_DATA=/var/lib/marka .venv/bin/marka login
sudo -u marka env MARKA_DATA=/var/lib/marka .venv/bin/marka doctor --live
```

Установите unit после проверки путей. Этот вариант поддерживает чат, память,
веб и файлы; `code.run` отключён, пока не подключён отдельный sandbox container.
Не запускайте runner как обычный host-процесс.

## Локальная модель поиска

Для нативной установки дополнительные пакеты ставятся через
`.venv/bin/pip install '.[semantic]'`; образ Compose уже содержит их.
Команды выполняются с тем же `--data` или `MARKA_DATA`, что и bot:

```bash
docker compose run --rm --no-deps mark models install
docker compose run --rm --no-deps mark models status
docker compose run --rm --no-deps mark models index --limit 1000
```

`--limit` ограничивает число источников за один проход. После большого импорта
индексирование можно продолжать следующими проходами; фоновые небольшие порции
выполняются, когда нет готовой задачи. Лексический поиск доступен независимо
от установки модели. Индексы хранятся как производные данные SQLite и проверяют
актуальность исходного текста; они не заменяют резервную копию канонических событий.

Каталог `/state/models/multilingual-minilm` содержит закреплённые `model.onnx`,
`tokenizer.json`, локально полученный `model.ort` и `manifest.json`. При переносе
готовой модели копируйте **весь каталог**, сохраняя manifest и права доступа,
затем выполните `models status`. ORT-файл привязан к поддерживаемой версии
runtime; его хеш локального преобразования записан в manifest. Одна копия ONNX
или ORT без остальных файлов не составляет готовую установку. При несовпадении
версий переустановите модель штатной командой; пользовательские тексты при
локальном вычислении embeddings не отправляются в отдельный внешний API.

## Импорт личного контекста

```json
[
  {"kind":"preference","level":1,"key":"style","content":"Предпочитаю краткие ответы с проверяемым результатом."},
  {"kind":"lesson","level":2,"content":"Перед повтором неудачной команды сначала выяснить причину ошибки."}
]
```

Передайте JSON в приватный state-том и выполните `marka import-memory /state/seed.json`.
По умолчанию записи попадут в кандидаты. `--accept` используйте только для лично
проверенных исходных утверждений. Полный архив чатов не нужен при каждом запросе.

Для истории используется отдельный JSONL-импорт, по одному сообщению на строку:

```json
{"external_id":"conversation-1/message-1","role":"user","created_at":"2026-09-01T12:00:00+03:00","content":"Исходное сообщение","meta":{"conversation_id":"conversation-1"}}
{"external_id":"conversation-1/message-2","role":"assistant","created_at":"2026-09-01T12:01:00+03:00","content":"Исторический ответ, требующий проверки"}
```

```bash
docker compose run --rm --no-deps mark import-archive /state/imports/history.jsonl --source personal-chat-export-v1
docker compose run --rm --no-deps mark models index --limit 1000
```

Сначала передайте файл в приватный state-том, не добавляя его в Git. Имя `--source`
должно быть стабильным: оно вместе с исходным ID задаёт происхождение и повторяемый
импорт без дублей. Роли `user`, `assistant`, `tool`, `system` и исходные даты
сохраняются; указывайте часовой пояс, чтобы не выдумывать время. При отсутствии
даты используется явный технический маркер эпохи, а не время текущего импорта.
Длинные записи разбиваются на связанные части. Файл ограничен 512 MiB; импорт
идёт порциями, поэтому после ошибки уже принятые порции сохраняются, а повторный
запуск с прежним `--source` продолжает работу без повторных записей.

Весь архив остаётся непроверенной историей. Старый ответ ассистента не становится
фактом, а импортированные `system`/`tool` не получают прав текущих инструкций
или фактически выполненных инструментов. Принятие знаний выполняется отдельно.

## Если что-то не работает

- `doctor` различает наличие токена, авторизацию Codex и проверку базы.
- `doctor --live` дополнительно делает один реальный запрос модели.
- Ошибка входа в Codex: повторите `docker compose run --rm --no-deps mark login` в **том же state-томе**; при нативной установке — `marka login` с прежним `MARKA_DATA`.
- Telegram 401: проверьте актуальность токена бота в приватном `settings.json`; вход в Codex его не исправит.
- Лимит подписки: дождитесь сброса и `/resume номер`; платный API автоматически не включается.
- Telegram 409/webhook: проверьте, что токен принадлежит новому боту и не используется другим polling/webhook.
- `blocked` после перезапуска во время инструмента: изучите результат `/result` и файлы, затем явно `/resume`.
- Неопределённая доставка: `/result номер` запросит ответ повторно по вашему решению.
- Нет runner socket: `docker compose logs sandbox`, затем изолированный smoke test.
