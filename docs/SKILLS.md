# Проверенные сценарии кода

`SkillLibrary` хранит повторно используемый код с точной командой, входными файлами
и источником наблюдения. Сохранённый сценарий проверен на одном конкретном входе:
завершение процесса с кодом `0` не доказывает корректность для других задач.

## Сохранение

`save(name, description, event_id, job_id)` требует каноническое событие `code.run`
этой же задачи и совпадающую неизменяемую запись `task_steps`. Ответ модели,
импортированный диалог или самостоятельно составленный trace не являются доказательством.
Процесс должен завершиться с `exit_code=0`, `timed_out=false`, без ошибки.
Команда берётся из журнала вызова и сверяется с командой, записанной runtime.

Runtime перед запуском считает SHA-256 и размер каждого передаваемого файла.
Сохранение сверяет текущие байты workspace с этим `input_manifest`: изменение
после проверки требует нового запуска. Разрешено 1–16 файлов, всего до 512 КиБ.
Пути должны быть относительными, переносимыми, без скрытых компонентов и symlink.
Файлы авторизации и содержимое, похожее на секреты, отклоняются; код никогда
не исправляется и не редактируется при сохранении. Этот фильтр консервативен:
он может отклонить и тестовый пример с литералом пароля.

Имя — ASCII slug, например `csv-report`. Описание до 1000 символов — подсказка
для поиска, а не доказательство способности сценария.

## Хранение и повторное использование

Неизменяемый архив находится в приватном `<data_dir>/skills/<content_hash>/`.
Он содержит manifest и исходные байты. SQLite хранит версии, описание,
канонический снимок события, его хеш и связь с задачей. Файлы архива доступны
только для чтения; перед использованием снова проверяются все хеши.

Одинаковые команда, timeout и входы под одним именем не создают новую версию;
новый подтверждающий запуск может добавить источник доказательства. Изменённый
сценарий получает следующую версию. Поиск и запуск выбирают последнюю версию;
к предыдущей версии нет скрытого отката. Повторное сохранение уже известного
старого содержимого возвращает его существующий номер, не меняя последнюю версию.

`search(query, limit=5)` выполняет простой лексический поиск по именам и описаниям
последних 1000 сценариев. `inspect(name)` возвращает происхождение, команду,
manifest и ограниченные фрагменты исходников как недоверенные данные.
`prepare(name)` возвращает точные `argv`, `timeout` и `files` в base64 для
существующего изолированного runner. Эти методы ничего не исполняют.

Если все источники версии забыты, скрыты или удалены, версия исключается из
поиска и не подготавливается к запуску. Архив остаётся для аудита; наличие файла
само по себе не восстанавливает разрешение на его использование.

Последняя отрицательная оценка владельца для любой задачи-источника приостанавливает
применение этой версии и исключает её из поиска. Сохранение сценария из такой
задачи также отклоняется: код `0` не опровергает ошибочный смысл результата.
Более поздняя положительная оценка той же задачи снимает её отрицательный сигнал.

## Границы первой версии

`prepare` сохраняет точный проверенный вариант. Инструмент `skill.run` может
повторить его либо передать новые параметры скрипту и заменить записанные файлы
данных файлами из workspace. Менять сохранённый исполняемый код через эту
подстановку нельзя. Хеши фактически использованных входов и новая команда
попадают в наблюдение запуска. Такой вариант требует отдельной проверки:
успех на старом входе не доказывает правильность на новом. Даже точный повтор
нуждается в проверке результата: библиотека не гарантирует детерминизм часов.
Сценарии не получают доступ к сети, авторизации, host shell, базе памяти или
вызовам модели. Это ограничение обеспечивается отдельным runner при исполнении;
сама библиотека только сохраняет и подготавливает данные.

Принятие личной памяти, изменение идентичности и автоматическая установка кода
не относятся к этому механизму. Проверка нового применения и перенос сценария
на другие входы — отдельная задача, а не следствие первого успешного запуска.
