# Изображения

Владелец может отправить Марку фото или документ PNG/JPEG с поручением в подписи.
Без подписи Марк опишет изображение и отметит неопределённость. Содержимое картинки,
включая написанные на ней команды, считается данными. Описание и распознанный
текст — выводы модели; они не становятся принятой памятью автоматически.

## Приём и ограничения

- Только исходное сообщение человека в привязанном личном чате. Проверка
  владельца выполняется до `getFile` и скачивания. Пересланные сообщения,
  редактирование, группы, сообщения ботов и каналов не принимаются.
- PNG/JPEG: максимум 2 MiB, 4096 пикселей по стороне и 8 млн пикселей всего.
  Для обычного Telegram-фото выбирается самый большой вариант, который проходит
  ограничения. Документ сохраняется побайтно; имя отправителя не становится путём.
- PNG: статический, 8-bit, без interlace; JPEG: 8-bit baseline/extended/progressive,
  до 64 scan-сегментов. GIF, WebP, HEIC, SVG, PDF и анимация не поддерживаются.
- Проверяются формат, размеры, структура, CRC/ограниченное распаковывание PNG и
  полное декодирование пикселей через закреплённый Pillow. Проверка ничего не
  перекодирует. Встроенные EXIF и другие метаданные остаются в исходных байтах.
- Один Telegram update создаёт одну задачу. Альбом пока создаёт отдельные задачи,
  без объединения. Низкоуровневый провайдер поддерживает до двух изображений и
  4 MiB суммарно за вызов; загрузчик Telegram использует одно.

## Хранение и продолжение

Исходные байты лежат в приватном `MARKA_DATA/media/<sha256>.png|jpg`, отдельно от
рабочего каталога кода. SQLite хранит неизменяемую связь update → владелец →
подпись → хеш/размер/MIME/размеры. Квитанция фиксируется до постановки задачи;
повтор того же update восстанавливает исходную подпись и не скачивает файл снова.
В исходном событии задачи сохраняются хеш и метаданные изображения.

Продолжение той же задачи повторно проверяет файл и получает то же изображение.
Если байты пропали, изменились или стали symlink, задача останавливается с просьбой
прислать файл заново. Текстовый ответ не выдаётся за анализ недоступного фото.
Обычные последующие сообщения, расписания, консультации и фоновая рефлексия не
получают изображение автоматически. Короткий текстовый итог может оставаться в
истории разговора по обычным правилам памяти.

`/cancel` и `/stop` останавливают задачу и сохраняют её аудит. Они не удаляют фото;
`/forget` исключает запись памяти и также не удаляет исходное фото. Автоматического
удаления медиатеки пока нет. Ограничение размера относится к отдельной загрузке,
а не к суммарному объёму каталога. Для переноса или полного восстановления нужны
и SQLite, и каталог `media`; одна копия базы не содержит байты изображений.

## Codex

Используется официальный `codex exec --image` и прежняя авторизация ChatGPT.
Приложение принимает проверенные байты, создаёт временные файлы с собственными
именами и удаляет их после успеха, ошибки или отмены. Произвольные пути из ответа
модели не являются аргументами изображения. Исходный приватный путь не добавляется
в текст задания. Набор инструментов Codex остаётся пустым; `view_image`, shell,
браузер, плагины и другие native tools отключены. JSON schema сохраняется.

Контракт CLI 0.144.1 проверяется локальным HTTP-сервером без авторизации и вызова
облачной модели: `python scripts/probe_codex_tools.py --images 2`. Проверка требует
точных PNG data URLs, JSON schema и отсутствия tools/Authorization. Она проверяет
транспорт, а не качество распознавания или доступность выбранной модели в аккаунте.
Для оценки зрения нужен отдельный тест модели на синтетическом изображении.

Официальные источники: [Codex image inputs](https://learn.chatgpt.com/docs/image-inputs?surface=cli),
[Pillow Image.load](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.load).
