# Голосовые через OpenAI API

Марк принимает исходные голосовые владельца в личном Telegram-чате:
**OGG/Opus до 2 MiB и 60 секунд**. Аудио отправляется в OpenAI Transcriptions API
с моделью `gpt-4o-transcribe`; язык определяется автоматически. Ответ Марка
приходит текстом. Синтеза голоса, видео и произвольных аудиодокументов пока нет.
Пересланные сообщения, группы и чужие аккаунты не обрабатываются.

Это отдельный API-расход по ключу OpenAI. Подписка Codex используется для
рассуждений и ответа, но не оплачивает этот запрос распознавания. Если ключ
не подготовлен, бот объясняет это до скачивания аудио; состояние видно в
`/help` и `/status`. Наличие файла ключа означает настройку, а не проверенную
доступность API или наличие средств.

## Авторизация и обработка

Оператор сохраняет ключ в **`/state/openai-stt.key`**, владелец UID 10001,
права 0600. Ключ не вводится в Telegram, не хранится в Git/settings.json и не
передаётся через environment, argv, prompt модели или sandbox. Сам файл читает
только короткоживущий процесс HTTP-запроса. Symlink, чужой владелец, широкие
права, слишком большой или некорректный файл отклоняются.

Endpoint фиксирован: `https://api.openai.com/v1/audio/transcriptions`, multipart
`file=voice.ogg`, `model=gpt-4o-transcribe`, `response_format=json`, `stream=false`.
Нет изменяемого base URL, redirect, наследуемого proxy или неявного ключа из
окружения. JSON-ответ ограничен 48 KB, текст — 6000 символами, время запроса —
125 секундами. Ошибки не выводят Authorization или необработанный ответ сервера.

До отправки проверяются CRC и последовательность OGG-страниц, единый Opus-поток,
его завершение и длительность по Opus-пакетам, pre-skip и final granule. Метаданных
Telegram для лимита длительности недостаточно. Полное декодирование выполняет
OpenAI; локальной модели речи, FFmpeg, новых зависимостей или STT-контейнера нет.

## Память, повторы и отмена

Исходные байты лежат в приватном `/state/voice/<sha256>.ogg`, вне workspace.
SQLite хранит связь исходного Telegram update, владельца, подписи и хеша.
Повтор update и перезапуск не создают второго скачивания или новой задачи.
Расшифровка и текст задачи фиксируются одной транзакцией с проверкой lease.

Текст STT помечен `unverified_transcription`, включая последующий поиск и
раскрытие источника. Это производный текст, который может содержать ошибки,
а не дословная цитата владельца. Он не проходит через обработчик `/remember`,
`/learning` или иных управляющих команд и не становится принятым фактом сам.

Перед платным API-запросом записывается признак незавершённого действия.
Если процесс оборвётся до сохранения расшифровки, восстановление ставит задачу
в `blocked`: автоматической повторной оплаты не происходит. Если расшифровка
уже сохранена, продолжение использует её без повторного STT. Ошибка API также
останавливает задачу; после устранения причины доступна `/resume ID`.

`/stop` завершает локальный сетевой процесс. **Уже отправленный запрос мог быть
обработан и оплачен OpenAI**; отмена не отменяет этот расход. Явный `/resume`
после неопределённого результата может отправить аудио ещё раз. Автоматических
HTTP-повторов нет. Обычные Telegram-команды доступны во время распознавания.
Перед отправкой проверяется остаток общего бюджета задачи. Исчерпанная задача
не тратит STT API даже после `/resume`: сначала нужен `/extend`. Таймаут STT
сокращается до оставшегося времени задачи.

Ежедневный SQLite backup содержит квитанции и текст, но не аудиофайлы и не ключ.
Для переноса нужен защищённый полный state-том. Автоматического удаления аудио
пока нет; `/forget` не является физическим удалением исходного голосового.

## Проверка и источники

Тесты покрывают владельца, лимиты, квитанции, сбои до/после ответа, replay,
отмену процесса, секреты, multipart, redirect, ошибки и ограничение ответа.
`scripts/voice_smoke.py` делает ровно один реальный API-запрос на синтетической
русской записи, затем проверяет продолжение после сбоя без второго запроса.
Он не использует Telegram и не отправляет личный голос владельца.

На проверке 19 сентября 2026 года один реальный запрос `gpt-4o-transcribe`
принял OGG/Opus длиной 7.843 с и вернул точный текст синтетической русской
записи за 1.503 с. Все 10 проверок smoke прошли, повтор после сохранения
расшифровки обошёлся без второго запроса. Зафиксированный снимок полной регрессии:
369 тестов на Linux (1 platform skip) и 369 на Windows (13 platform skips),
остальные прошли. Это проверка конкретного сценария, не обещание такой же
скорости или точности на любой записи. Реальный голосовой Telegram-цикл
владельца этим синтетическим тестом не проверяется.

[OpenAI Transcriptions API](https://developers.openai.com/api/reference/python/resources/audio/subresources/transcriptions/methods/create)
описывает multipart и поддержку OGG;
[gpt-4o-transcribe](https://developers.openai.com/api/docs/models/gpt-4o-transcribe)
— выбранная модель. Формат Opus и длительность пакетов определены в
[RFC 6716](https://www.rfc-editor.org/rfc/rfc6716.html#section-3.1).
