# Работа, которая видна и проверяется

Начиная с 2.6, worker поддерживает Telegram `typing` примерно раз в четыре
секунды, пока выполняется текущая задача, включая подготовку голосового.
При завершении, ошибке или отмене фоновая корутина останавливается. Telegram
сам убирает последний индикатор в течение пяти секунд либо после сообщения
бота; отдельной команды отмены у [sendChatAction](https://core.telegram.org/bots/api#sendchataction)
нет. Индикатор означает активную обработку, а не успешность результата.

В защищённой установке требуется обновление закреплённого bridge. Его новая
операция принимает только ID привязанного владельца, всегда использует действие
`typing`, ограничивает частоту и время запроса. Статус не попадает в очередь
доставок или квитанции внешних эффектов. Сетевая ошибка индикатора не останавливает
полезную работу; 429 учитывается, повторные ошибки прекращают индикатор.

Модель больше не отправляет промежуточное сообщение перед каждой попыткой
инструмента. Текстовые обновления сообщают о наблюдавшемся сохранении файла,
выполнении проверки, фиксации критериев или завершении эксперимента. Простое
чтение поддерживает индикатор активности без повторных сообщений «проверяю…».

## Сохранённые результаты и навигация

`task_working_memory` содержит прочитанные исходники с хешами, страницы и номера
шагов. Полные наблюдения остаются в журнале и исходных событиях. Их можно заново
прочитать через `task.recall`: номер шага относится только к текущей задаче,
а большие ответы выдаются по страницам. Событие проверяется по автору, сессии,
задаче, инструменту и сохранённому результату либо его хешу. Ответ снова
маскируется перед передачей модели. Это чтение не повторяет исходную операцию.

Сокращённые ответы инструментов остаются корректным JSON с явной пометкой
сокращения. Они не выдаются за полный исходник. `self.search` ищет буквальный
текст в установленных публичных исходниках и тестах; `self.inspect` возвращает
точные страницы до 12000 символов, `next_offset` и хеш. Права на файлы сервера
от этого не расширяются.

## Повторы и бюджет

Повторные одинаковые чтения вызывают предупреждение в контексте. Пятое
одинаковое чтение либо четвёртая одинаковая ошибка останавливают задачу с
сохранением журнала. Детектор также учитывает серию повторов без новых данных.
Разные страницы и изменившиеся данные не считаются одинаковыми ответами.
Успешное действие сбрасывает счётчик; текстовый план этого не делает. Неуспешный
код или отвергнутый эксперимент не считаются успехом только из-за ответа RPC.
Это ограниченный детектор конкретных повторов, а не универсальная оценка
полезности каждого шага.

`/resume` сохраняет использованный бюджет. Если исчерпаны шаги, вызовы или
общее время, он объясняет необходимость `/extend`, не переочередивает задачу
и не создаёт разрешение на повтор платного обращения. `/extend` добавляет
бюджет по настоящей команде владельца. Увеличение бюджета само по себе не
исправляет неудачный подход.

Самоизменение бота не обновляет закреплённый bridge. Новые сетевые операции
bridge требуют операторского выпуска. Ограничения размера кандидата также
сохраняются и видны при чтении исходников. Ни индикатор, ни новые инструменты
не доказывают, что произвольное самоулучшение будет успешным.
